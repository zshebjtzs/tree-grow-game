## 项目简介

本项目是对 B站 UP主 **“浩辰-_-”** 原创纸上游戏《生长树》的数字化重制。在保留原版“图论与面积争夺”核心玩法的基础上，本项目进行了深度拓展：

- **自动化生成地形**：采用 Voronoi 图算法，每局自动生成 50 个多边形战棋区域。
- **大幅提升视觉体验**：引入 Lloyd 松弛算法，生成极度均匀的“蜂窝状”地图。
- **智能图论规则引擎**：实现严谨的图论回溯（直接摧毁、连锁摧毁、免疫堡垒、分支点冻结）。
- **内置离线 AI 引擎**：引入 Web Worker 构建非 LLM 的启发式 AI，提供 3 个不同难度的单机对战体验。

## 功能特性

| 模块 | 子功能 |
| --- | --- |
| **双人热座对战** | 本地同设备双人轮流操作，无需网络，无缝切换。 |
| **单机 AI 对战** | 基于启发式打分算法的 AI（非 LLM）。提供 **简单**（策略犯错）、**普通**（加权随机）、**困难**（绝对理智择优）3 档难度。 |
| **地图生成引擎** | 基于 `d3-delaunay`，每次开局生成完全不同的 50 区地图。配合 Lloyd 松弛算法及极长/极短边阻断，杜绝视觉伪邻接（飞线）。 |
| **图论战斗核心** | 生长受限于“单步穿线”；战斗时支持**直接摧毁分支点**、**连锁摧毁向上回溯**、**免疫堡垒**（>3条连接）绝对防御。 |
| **战略冻结机制** | 当敌方切断你的某条树枝时，幸存的上游分支点将在**下一回合被冻结**，无法生长，有效防止双方陷入局部“绞肉机”拉锯战。 |
| **本地单文件存档** | 基于浏览器 `File System Access API`，支持自由保存和读取 `*.sav` 文件到本地电脑。 |
| **纯前端免环境** | 所有代码打包为一个 `bundle.js`，配合 `index.html` 和 `style.css`，**无需安装 Node.js 或数据库**，双击即可运行。 |

## 快速开始

### 普通玩家（开箱即玩）

本项目**无需安装任何开发环境**（无需 Node.js，无需数据库）。
1. 前往本项目的 **[Releases](https://github.com/zshebjtzs/tree-grow-game/releases)** 页面。
2. 下载最新版本的 `tree-grow-game.zip`。
3. 解压后，找到 `index.html`，**直接双击** 用浏览器（Chrome/Edge 皆可）打开即可游玩。

### 开发者本地运行

如果你想在 VS Code 中修改代码或进行二次开发：

1.  **克隆仓库**

   ```bash
   git clone https://github.com/zshebjtzs/tree-grow-game.git
   cd tree-grow-game
   ```

2.  **运行开发模式**

   本项目采用原生 ES Modules 开发，打开 VS Code 后，安装 **[Live Server](https://marketplace.visualstudio.com/items?itemName=ritwickdey.LiveServer)** 插件。在 `index.html` 上右键点击 **"Open with Live Server"**，即可在浏览器中实时调试。

3.  **重新打包（生成 bundle.js）**
   当你修改了 `js/main.js` 及各个模块文件后，为了让你或者朋友可以 `双击 index.html` 直接运行，需要重新打包：
   ```bash
   npm install -g esbuild # 如果没装过 esbuild
   npx esbuild js/main.js --bundle --outfile=js/bundle.js --external:d3-delaunay --format=esm
   ```

## 核心规则手册

《生长树：图论》的核心是一套基于 **有向树** 与 **拓扑地图** 的严谨规则。所有战斗、移动和摧毁都严格遵循图论回溯算法。以下是完整的官方规则说明：

### 一、 基础定义
*   **根节点 (Root)**：游戏开局时，在双方基地内自动生成的 3 个起始节点。根节点是整棵“树”的生命之源。
*   **叶节点 (Leaf)**：树木生长的末端节点（没有子节点）。
*   **分支点 (Branch Node)**：连接了 **≥3条** 树枝的节点。它是整棵树承上启下的核心枢纽。
*   **区域 (Region)**：地图上由黑线围成的封闭多边形空间，是玩家的最小领地单元。

### 二、 生长与领土扩张（移动规则）
玩家在每个回合中，必须从己方的一个节点出发，画出一条新树枝并落下一个新叶节点。

*   **绝对铁律（无环限制）**：**节点与节点之间不能直接相连**。每次行动必须且只能伴随一次“生长”。
*   **单步穿线限制（普通枝干）**：除了根节点的初生枝条外，**所有后续的新树枝只能穿过一条黑线**，进入与当前节点区域紧邻的下一个区域。绝对禁止直接跨越多个区域（防止视觉飞线）。
*   **根节点初生限制**：根节点伸出的**第一根树枝**，享有“开拓特权”，最多可以跨越 **2 块** 己方已占据的区域（让基地能够向外交互）。
*   **禁止跨越领地**：树枝在延伸时，绝对**不可跨越任何已被占据的区域**（无论是己方还是敌方的领地区域，皆不可跨越）。
*   **区域据点控制**：
    *   **己方基地**：允许容纳 **3** 个根节点。
    *   **除基地外的所有普通区域**：**最多只能容纳 1 个己方节点**。玩家必须规划好每一条枝干的延伸方向，无法在同一个区域堆叠据点。
*   **严禁回退**：禁止向己方基地所在的区域生长（防止绕回老巢无脑发育）。

### 三、 战斗与摧毁机制（图论核心）
当一个玩家的新叶节点，落在了敌方已有节点所在的**同一区域**时，立即触发战斗。战果根据敌方节点的属性判定：

*   **情况一：直接摧毁（断根与斩首）**
    如果该敌方节点是一个连接数 **≤3条** 的脆弱分支点。敌方主干将被系统**连根拔起**。该分支点及其下属的所有树枝、叶节点将被全部抹除。
*   **情况二：连锁摧毁（削枝与修剪）**
    如果该敌方节点是叶子或单链节点。系统将沿着树的结构**向上回溯**，寻找最近的一个上游分支点。该分支点**绝对安全（幸存）**，但分支点下属的“被攻击枝叶”到“分支点”这一段整条树干，将被**彻底切断并摧毁**。
*   **情况三：免疫堡垒（绝对防御）**
    如果该敌方节点是一个连接数 **>3条** 的超级节点。它将化作一座**免疫堡垒**。敌人不仅**无法直接摧毁**它，甚至**完全无法踏入**该堡垒所在的区域。

### 四、 防守与冻结机制（防止拉扯绞肉）
为了打破双方在局部区域反复拉扯的死局，游戏引入了**“分支点冻结（熄火）”**规则。

*   **触发冻结**：每当敌人的进攻触发了**连锁摧毁**（削枝），被摧毁的“起始点”如果在摧毁中幸存，它会立刻被施加“冻结”状态。
*   **冻结效果**：在被冻结方**接下来的这一整个回合**中，该节点**无法被选中**作为新树枝生长的起点（点击会提示“本回合处于休整状态，无法生长”）。
*   **解除冻结**：防守方玩家可以在这一个回合内，**利用其他未被冻结的节点走一步**，或者直接点击右上角的 **“跳过回合”**。一旦完成了自己的回合行动，该节点上的冻结状态会立刻自动解除。
*   *设计目的：这条规则迫使玩家在局部领地遭受损失后，必须将战略重心转向地图的其他空白区域，从而真正利用好 50 个区域的大地图，杜绝双方死磕一个小角落的僵局。*

### 五、 胜利条件
游戏将在达成以下任意**一项**条件时立刻结束并宣告胜者：

1.  **战略突入（攻入敌营）**：己方的新树枝成功生长并踏入**敌方基地**所在的区域。
2.  **彻底覆灭（斩尽杀绝）**：成功将敌方**所有 3 个根节点**全部摧毁（无论是通过直接摧毁还是连锁摧毁）。

## AI 机制与难度

- AI 运行在独立的 **Web Worker** 线程中，不会因为算路而卡死主界面。
- AI 采用**启发式打分**策略，即时评估“能否吃子”、“能否突入敌方基地”、“风险规避”等因素。
- **简单难度**：策略具有随机性，适合新手熟悉规则。
- **普通难度**：加权随机选择高分动作，有一定战术意识，但不死板。
- **困难难度**：绝对理智，永远只选择当前打分最高的最优解，适合极限锻炼。
