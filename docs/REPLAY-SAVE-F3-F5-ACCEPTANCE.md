# TreeGrow F3–F5：大型存档与回放性能验收

## F3：后台导入
- 解码、gzip 解压、JSON 解析及地图/节点/行动链校验在 ES Module Web Worker 中运行。
- UI 显示导入阶段；取消通过 terminate Worker 中止当前任务。
- Worker 完成验证前不替换现有回放；失败不会污染当前会话。
- 不支持 Worker 的运行环境保留主线程兼容路径。

## F4：长棋谱回放 UI
- 行动列表使用固定高度虚拟窗口，DOM 数量只随可视区域和 overscan 增长。
- 每步标题、行动说明和事件摘要导入后缓存。
- ReplaySession 冻结内部历史，播放控制器使用只读快照视图，避免每步复制完整快照。
- 地图底图只在导入时绘制一次，播放时仅更新节点图层。
- 对外保留防御性复制 getter。

## F5：自动化验收
- Worker 导入任务：压缩存档、PVE 后手元数据、旧存档无棋谱、损坏棋谱。
- 时间线窗口：短棋谱、10 万步、滚动边界、非法参数。
- ReplaySession：摘要缓存、只读视图、输入隔离。
- 既有验证器、压缩、悔棋和控制器测试继续运行。
- GitHub Actions 通过 Node 测试、生产构建、Pages 输出检查和 Windows Desktop Build。

## 手动设备验收
1. 导入旧版 JSON 存档与新版 gzip 存档。
2. 导入超过 20 MiB 的有效存档，确认不因体积被拒绝。
3. 导入损坏存档，确认失败且不替换上一次成功回放。
4. 导入长棋谱时观察进度；点击取消后确认任务停止，之后仍可重新导入。
5. 在长棋谱中滚动行动列表，确认选中步骤、进度条和棋盘同步。
6. 测试连续播放、暂停、倍速、首步/末步及任意跳转。
7. 对 PVP、PVE 红/蓝玩家和包含悔棋的存档分别验收。
8. Pages 与 Windows 离线桌面版各完成一次压缩存档导入。

## 性能记录
运行 npm run benchmark:replay，记录 JSON 字节数、压缩后字节数、压缩比、序列化耗时、校验耗时与编码耗时。真实设备峰值内存和交互流畅度仍需在手动验收中记录。
