# A8：AI 棋力恢复与六档难度重建

## 目标与验收原则

本阶段处理 AI 重构后的实际棋力退化，并重新建立六档难度梯度。目标不是单纯增加搜索预算，而是恢复可靠的战术能力、避免明显低级错误，并形成连续且可感知的强度层次。

约束：
1. 六档均须识别合法的立即获胜行动。
2. 六档均须优先处理对方的直接致胜威胁，并避免可预见的根节点重大损失。
3. 难度差异不能主要依赖高随机性或故意制造低级错误。
4. 相邻难度应有可测量、可感知的差异，避免强度跨度过大。
5. 新版 Hard 应恢复旧版 Hard 的基准棋力；新版 Expert 应在统一测试集上具备超过旧版 Hard 的目标表现。
6. 任何权重、预算或搜索策略调整都必须通过固定局面测试和配对锦标赛验证，不能凭单局结果调参。

## A8.0：基准与退化审计

### 旧版与新版的已确认差异

对照 PR #33 的开发分支与 PR base main：
- 旧版难度配置除了搜索预算，还使用不同的评估权重。旧版 Hard 的 safetyWeight 为 1.3、structureWeight 为 1.18；旧版 Expert 分别为 1.55 和 1.48。新版六档使用统一评估权重，主要通过最大深度、搜索时间和节点预算区分。
- 旧版 Easy 使用 varied 选择，Medium 使用 weighted 选择，Hard/Expert 使用搜索。新版六档统一进入搜索流程，移除了上述选择机制。
- 新版评估器增加了 unsafeRoots、rootChainRisk、softDistanceToBase、growthHeadroom、baseThreatCount、近基地堡垒等结构指标。它们的引入不等于棋力提升；权重方向、量纲和相互作用仍需专项验证。
- 新版搜索时间预算从进入 SearchEngine 后才开始计时；根候选生成、模拟、静态评分和战术防守筛选发生在此之前。因此 profile 的 searchBudgetMs 不是完整 AI 决策的端到端时间上限。该问题可能影响响应时间和实际可完成搜索工作量，需拆分测量。
- 新版取消了根层静态 Top-N 截断，保留全部合法根候选。这扩大了候选覆盖，但也可能增加根层计算成本；其棋力影响必须通过相同局面实验确认。

以上均为代码差异，不应直接当作棋力退化的已证实根因。

### 用户提供的对局存档：首个回放样本

存档 growth_tree_save.sav 可解压读取，包含完整的 matchHistory.actions、初始快照、地图种子和双方基地信息。样本为 PVE、Hard，红方玩家，蓝方 AI，最终红方在第 11 个行动突入蓝方基地获胜。

蓝方 AI 的行动序列：

| 行动序号 | AI 行动 | 后续情况 |
|---:|---|---|
| 2 | 从根节点 4 生长到区域 16 | 未发生攻击 |
| 4 | 从根节点 5 生长到区域 8 | 下一手被玩家攻击，连锁摧毁 2 个节点并损失一个根 |
| 6 | 从节点 8 生长到区域 5 | 下一手被玩家攻击，连锁摧毁 3 个节点并再损失一个根 |
| 8 | 从根节点 6 生长到区域 15 | 继续扩张 |
| 10 | 从节点 14 生长到区域 1 | 继续扩张，下一手玩家突入基地 |

该局蓝方 AI 共生长 5 次、攻击 0 次；玩家两次攻击分别摧毁 2 和 3 个节点，AI 共损失 2 个根节点。该局是明确的战术失败样本，但单局不能证明所有局面或所有难度均退化。

### 首轮审计假设

以下为待实验验证的假设，不是已确认根因：
1. 战术防守覆盖不足：当前 rankDefenses 主要针对对手下一手立即获胜威胁；它未必能识别下一手虽不能直接获胜、但可摧毁根节点或重要链条的重大战术威胁。
2. 结构指标权重失衡：新增指标可能使静态评估偏好扩张、可生长父节点数量或近基地结构，而低估对手下一轮的实际攻击收益。
3. 难度区分机制退化：旧版 Hard/Expert 有不同评估权重，新版完全共享权重；只靠预算区分可能没有形成预期的棋力层次。
4. 搜索准备阶段消耗未纳入预算：高分支局面可能在正式搜索前消耗大量时间，降低有效搜索工作量。
5. 搜索行动排序与叶节点评估不匹配：需要检查根候选排序、内部节点排序和战术价值是否一致，尤其是攻击、反击和防守行动。

## A8.1：固定局面与决策差分

建立可复现的局面集，至少覆盖立即获胜与阻止立即获胜、根节点直接受威胁和根链级联摧毁、多根同时受威胁、进攻与防守取舍、多步连锁摧毁、基地竞速与路径阻断、多分支扩张和低分支残局。

每个局面记录六档 AI 的候选行动评分、战术标签、选中行动、完成深度、节点数、搜索耗时、准备阶段耗时和总耗时。旧版 Hard/Expert 必须在相同局面上作为基准。

优先对存档中蓝方 AI 的第 4、6、8、10 个行动前快照进行复现，检查合法行动集合、可预见攻击和 AI 实际选择。回放必须使用存档的初始快照、行动历史和地图种子；不得用最终局面倒推替代真实历史局面。


### A8.1 首轮代码核查：已确认的战术覆盖缺口

对照 main 与 PR 开发分支的 `js/ai/TacticalAnalyzer.js`，两者实现相同。当前战术层只有两类检查：
- `findImmediateWinningMove`：选择本方当前即可进入敌方基地的行动。
- `rankDefenses` / `countImmediateWinningMoves`：统计并减少对手下一行动即可获胜的数量。

该模块没有检查对手下一行动是否能够：
- 摧毁本方根节点但尚不足以立即结束对局；
- 通过连锁摧毁造成多节点损失；
- 破坏根节点与其关键分支之间的连接；
- 在多根结构中连续削弱防守能力。

因此，代码层面已确认：当前所谓“必要防守”实际上只覆盖对手立即获胜威胁，并不覆盖根节点与根链的重大战术威胁。这与存档中 AI 两次在玩家可攻击区域落子、随后分别损失一个根节点的表现相吻合。它是高度相关的缺陷候选，但仍需在存档历史局面上运行合法行动模拟，确认当时是否存在避免损失的防守行动，以及 AI 为什么没有选择。

另一个已确认的设计变化是：旧版 Hard/Expert 通过不同的 safety、structure、attack 等权重形成行为差异；新版统一了这些权重。该变化本身不是 bug，但意味着新版必须通过搜索预算之外的有效搜索质量来证明梯度，不能仅以预算递增代替棋力验证。

### A8.1 实验执行约束

存档包含完整的 `matchHistory.initialSnapshot` 与 `matchHistory.actions`，可用于逐步恢复历史局面；最终 `gameState` 只能用于核对终局，不能代替中间决策局面。复现时必须使用相同的地图种子生成邻接关系，并对每个 AI 决策点分别记录：
1. AI 决策前局面快照；
2. AI 全部合法行动；
3. 对手所有合法回应及其 CombatResolver 结果；
4. 各行动导致的根节点损失数、连锁摧毁节点数和基地威胁变化；
5. 旧版与新版各难度最终选择及其搜索统计。

在完成上述复现前，不修改评估权重、搜索预算或随机策略，以免破坏基准可比性。


### A8.1 回放分析工具：首版已提交

新增 `scripts/analyze-ai-save.js`，命令：

```bash
npm run analyze:ai-save -- ./growth_tree_save.sav
```

可选参数：

```bash
npm run analyze:ai-save -- ./match.sav --difficulty hard,expert
npm run analyze:ai-save -- ./match.sav --side blue
```

工具执行流程：
1. 读取 TGSV + gzip 或普通 JSON 存档。
2. 调用正式 `ReplaySaveValidator`，验证地图种子、初始快照、行动前后快照、行动顺序和完整历史链。
3. 用存档地图种子重建 1800×1200 地图及邻接关系，并重复重建核对拓扑确定性。
4. 按历史记录逐一恢复指定阵营每次生长行动前的真实局面。
5. 对指定难度调用正式 `AIController`，记录选择、是否匹配历史行动、候选数、搜索统计与完整决策耗时。
6. 对每个合法候选行动枚举对手下一回合的合法回应，复用 Adapter 的正式模拟与 `CombatResolver`，统计回应可能造成的根节点损失和节点损失。

首版限制：
- 当前工具只分析存档中实际出现的历史局面，不自动生成更广泛的战术局面集。
- 反事实指标是“对手下一回合可实现的最大根/节点损失”，不是对手必然会选择该回应，也不是完整 minimax 结果。
- 首版只运行当前分支的六档 AI；旧版 Hard/Expert 的跨提交对照需要后续增加基准版本执行机制。
- 该工具尚未在 CI 中读取用户存档。CI 增加 CLI 启动回归测试；真实存档分析需在本地执行并保存 JSON 输出。
- 工具分析前会先通过完整历史校验；如果存档格式或历史链不合法，会明确失败，不会静默跳过。

本次未修改 AI 评估权重、预算或选招逻辑。完成本地真实存档运行前，不将该工具的分析结果视为棋力修复证据。

## A8.2：战术可靠性

基础战术保障不因难度降低而关闭。至少要求：
- 存在合法立即获胜行动时，所有难度均选择立即获胜。
- 存在可完全消除对手立即获胜威胁的行动时，所有难度均不得选择明显无关行动。
- 识别对方下一轮可造成根节点损失的直接攻击，以及可通过连锁摧毁造成重大损失的行动。
- 在无法完全防守时，优先比较最小化损失、反击和基地竞速的结果。
- 规则判定必须复用正式 RuleEngine / CombatResolver，不得另写近似规则。

战术保障应与通用搜索分层，但不能把所有可能防守粗暴地设成硬约束；需要通过合法模拟与反事实比较识别真正必要的防守。

## A8.3：六档难度校准

难度差异以稳定的决策能力梯度为主，不以大幅随机选招制造差异。
- Beginner：能处理直接胜负和明显根威胁，但规划视野较短。
- Easy：基础战术稳定，具备有限的局部连续规划。
- Medium：能够处理常见多步攻防和局部交换。
- Advanced：能兼顾多处威胁，形成中期攻防计划。
- Hard：能识别复杂战术组合并维持整体战略。
- Expert：在更广泛的候选和更深的搜索中，减少可避免的战术与战略失误。

可实验调整的维度包括搜索深度、节点/时间预算、战术延伸、候选排序精度和评估特征精度。不得未经实验就把随机性作为主要档位差异。

## A8.4：评测与验收

评测分三层：
1. 战术局面集：统计各难度的直接胜利命中率、必要防守命中率、根节点重大损失漏判率。
2. 旧版基准对照：新版 Hard 对旧版 Hard；新版 Expert 对旧版 Hard；所有比较使用相同地图、初始局面、先后手交换。
3. 六档配对锦标赛：使用多个独立地图种子，红蓝互换，记录胜平负、配对得分率、置信区间、对局长度、攻击转化、根节点损失和决策耗时。

不能仅凭搜索深度、节点数或一场对局的胜负宣称棋力提升。最终通过标准需在获得基线样本后制定，不能事先编造胜率阈值。
